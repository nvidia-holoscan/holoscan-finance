Calculation, data quality and timing details

Returns use quote midpoints at fixed event-time intervals. Both endpoints must be fresh. Invalid, crossed, wide, zero-size or explicitly halted quotes invalidate the mark. Only instruments with valid returns throughout the current window and nonzero variance enter the matrix. Trades are displayed separately. Observed volatility is a historical estimate, not implied volatility or a forecast.

Covariance uses the sample denominator n−1. Annualization assumes 252 trading days × 6.5 hours. NYQ denotes consolidated instruments primarily listed on NYSE. This replay uses the supplied quote fields and does not independently reconstruct or validate NBBO. Intraday sampling remains exposed to microstructure effects; freshness and window length affect the estimates. The first estimate needs the minimum number of completed return bars; seek, loop and restart rebuild that history.

Each comparison uses the same incremental BLAS calculation; ingestion continues while dedicated CPU and GPU workers compute. One comparison is in flight at a time, so the comparison cadence can be CPU-limited. GPU timing includes any host-to-device inputs and compact device-to-host outputs; full matrix transfer, JSON, browser rendering and process startup and process-to-process transfer are outside that timer. Arrival-to-result includes waiting and computation. MITCH carries market time, so sender-to-receiver latency is unavailable. Arrival-to-result uses the receiver clock. Rebuilds and startup samples are excluded from the rolling timing median.



Historical NYQ trade/quote replay with live computation. Quotes and trades are re-encoded using MITCH (MIT303 issue 11.9) over UDP. This is a replay mapping, not a native LSE feed or PCAP playback. The receiver mode appears under Network activity: kernel UDP or ConnectX/DAQIRI into pinned host memory followed by host decoding, or ConnectX/DAQIRI GPUDirect into GPU memory with GPU decoding and quote bars; analytics run on the selected backend.
